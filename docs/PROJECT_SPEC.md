# NOVA: Project Specification

## 1. Executive Summary & Purpose

**NOVA** is an embodied conversational agent and research-assessment platform for mental-health research, specifically investigating objective, involuntary biomarker signals associated with PTSD, anxiety, and psychological distress. 

### Critical Non-Negotiable Boundary
- **NOVA is strictly a research-assessment platform.**
- **NOVA is NOT an autonomous clinical diagnostic system.**
- **NOVA is NOT a therapist replacement or medical treatment device.**
- **NOVA is NOT an unconstrained or unrestricted chatbot.**

All computational outputs generated by the platform are framed and recorded as:
1. Observed behavioural and physiological evidence.
2. Multimodal research signals.
3. Model predictions calibrated with confidence intervals and signal quality metrics.
4. Explicit missing-modality flags when sensors degrade or fail.

No behavioural feature or multimodal prediction is ever reported as definitive proof of a clinical condition.

## 2. System Architecture & Scope

The system consists of five primary interacting layers:

1. **Unity 3D Embodied Virtual Human ("Nova")**
   - *Status*: Built and functional external client.
   - *Function*: Provides conversational embodiment, text-to-speech (TTS), synchronized lip-sync, and facial animation. Captures participant microphone audio and webcam frames.
   - *Communication*: Communicates with the FastAPI backend over HTTP REST and WebSocket connections.

2. **Python FastAPI Backend & Orchestration Service**
   - *Function*: Session lifecycle management, timestamp synchronization, real-time audio/frame ingestion, feature extraction coordination, modality alignment, Cross-Modal Transformer fusion execution, PPO question policy evaluation, safe question bank dispatch, and database persistence.

3. **Perceptual Processing Pipeline (Locked Modalities)**
   - **Speech (ASR)**: Pretrained Whisper model converting participant speech into timestamped transcripts.
   - **Text (NLP)**: Pretrained BERT-family encoder (e.g., DistilRoBERTa / BERT) generating contextual text embeddings.
   - **Voice / Audio**: Acoustic feature extraction comprising MFCCs, fundamental frequency (pitch / F0), cycle-to-cycle pitch perturbation (jitter), amplitude perturbation (shimmer), harmonics-to-noise ratio (HNR), and optional Wav2Vec 2.0 representations where specified.
   - **Face**: Facial landmark detection and Action Unit (AU) intensity/presence extraction via OpenFace / MediaPipe pipelines.
   - **Eyes / Gaze**: Ocular behavioural analysis capturing gaze direction vector, blink frequency/duration, and pupil metrics via MediaPipe Iris / GazeML-style processing.
   - **Physiological Channel (rPPG - Experimental & Isolated)**: Remote photoplethysmography estimating heart rate (HR) and heart rate variability (HRV). Strictly guarded by signal quality validation. If face tracking or illumination is substandard, rPPG is marked unavailable and masked; values are never fabricated.

4. **Cross-Modal Transformer Fusion**
   - *Role*: Primary multimodal fusion architecture.
   - *Design*: Modality-specific projection encoders project all signals to a shared dimension ($d_{model}$), aligned by conversational turn. Uses cross-modal multi-head attention where all available modalities attend to each other, followed by feed-forward layers with residual connections and layer normalization. Supports explicit binary modality masking $m \in \{0, 1\}^M$ to handle missing or corrupted channels gracefully.
   - *Outputs*: (a) Research assessment prediction head, (b) fused multimodal state vector $z_t$ feeding the RL policy, and (c) cross-attention weights providing explainable timestamped evidence.

5. **Adaptive Questioning Policy (PPO)**
   - *Role*: Selects the next assessment question based on the participant's multimodal state and session trajectory.
   - *Action Space*: Constrained strictly to a finite, clinically reviewed, safe predefined question bank. No arbitrary LLM question generation is permitted.
   - *Reward Formulation*:
     $$R_t = w_1 \cdot \text{InfoGain} + w_2 \cdot \text{TopicCoverage} + w_3 \cdot \text{Engagement} - w_4 \cdot \text{Repetition} - w_5 \cdot \text{Irrelevance} - w_6 \cdot \text{SafetyViolation}$$

6. **Researcher Dashboard & Persistent Data Infrastructure**
   - *Role*: Live session monitoring, real-time signal visualization, timeline inspection, session replay, longitudinal participant tracking across multiple interviews, and ablation experiment auditing.
   - *Audience*: Clinical researchers and affective computing scientists.

## 3. Dataset & Benchmark Specification

The benchmark foundation for offline model development and validation is the **DAIC-WOZ / Extended-DAIC (E-DAIC)** corpus (Distress Analysis Interview Corpus - Wizard of Oz):
- **Access Status**: Distributed under formal research license via University of Southern California (USC ICT).
- **Target Variable**: AVEC 2017 Depression Sub-Challenge PHQ-8 symptom severity score (continuous regression) and binary distress indicator ($\text{PHQ-8} \ge 10$).
- **Data Partitioning**: Strict participant-level splitting (Train, Validation, Test) to prevent data leakage across participant sessions.
- **Evaluation Tiers**:
  - Unimodal baselines (Voice, Text, Face, Gaze).
  - Multimodal ablation configurations:
    - $E_0$: Best single modality
    - $E_1$: Face + Voice
    - $E_2$: Face + Voice + Gaze
    - $E_3$: Face + Voice + Gaze + Text
    - $E_4$: Face + Voice + Gaze + Text + rPPG (active only if signal quality check passes)
  - Fusion comparison: Early fusion vs. Late fusion vs. Cross-Modal Transformer.
  - RL policy comparison: PPO adaptive questioning vs. Fixed question script baseline under identical turn budgets.

## 4. Hardware & Operating Environment

- **Operating System**: Windows 11 (64-bit)
- **Runtime Environment**: Python 3.12, Node.js v24.15
- **Hardware Acceleration**: Automatic device detection (`cuda` if compatible GPU present; graceful, memory-efficient fallback to `cpu`).
- **Database**: SQLite with SQLAlchemy ORM for reproducible local research records.
